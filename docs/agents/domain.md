# Domain Docs

## 布局

采用 single-context：

- 根目录 `CONTEXT.md`：领域术语及上下文。
- `docs/adr/`：架构决策记录。

本次仅配置消费规则，不创建空白 CONTEXT 或 ADR。

## 探索前读取

1. 如果根目录存在 `CONTEXT.md`，先阅读。
2. 阅读 `docs/adr/` 中与当前工作相关的 ADR。
3. 若后续改为多上下文且存在 `CONTEXT-MAP.md`，
   先阅读映射，再阅读相关上下文文档及局部 ADR。

文件不存在时静默继续。
领域建模技能在术语或决策明确后按需创建文档。

## 使用统一术语

Issue、设计建议、代码和测试名称使用 CONTEXT 定义的术语。
发现术语空缺时，记录供领域建模处理，避免自行引入冲突同义词。

## 决策冲突

建议与现有 ADR 冲突时，明确指出 ADR 编号和重新讨论的理由；
变更决策须显式记录。
